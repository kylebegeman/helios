Helios Ideas

Historical exploration of thirty-seven improvements to the Go rewrite of Ophelia. Many have since shipped. Use the current capability inventory and feature guides to distinguish delivered behavior from unselected proposals. The remaining ideas are a menu for review.

  • Items 1 to 19 are smaller improvements; 20 to 37 are systems and refactors.
  • Complexity: Small, Medium, Large, Massive. Impact: Low, Medium, High, Transformational.
  • Most items trace to something that went wrong this week or to a plan Ophelia wrote down and never built. The blueprint has that background.

Items 1 to 19

Minor features and improvements

Quality of life, workflow and maintainability. Most are small once the kernel exists, and several are the difference between a tool you tolerate and one you reach for.

1

helios doctor

SmallImpact: Medium
Summary
One read-only command that checks a machine the way I checked yours by hand this week.
How it works
Runs the daemon's own probes on demand: Docker and Caddy state, ports 80 and 443, disk, memory and swap, pending updates and reboot-required, certificate expiry, DNS agreement for every route, backup freshness, and anything running that Helios doesn't own. Prints pass, warn or fail with the fix for each; --json for scripts.
Experience
On a fresh box it tells you what setup will change. On a live box it's the first command when something feels off.
Why
The audit took a hand-written script, and it found updates waiting on a reboot on both machines that nobody knew about.
Unlocks
The same probes feed alerts (25) and the fleet view (32).
2

Everyday commands with readable names

SmallImpact: High
Summary
helios ps, helios logs <app> [workload], helios exec and helios status, with every container, network and volume named bedrock-<app>-<workload>.
How it works
Revisions live in Helios's state, not in names; the new container takes the name when traffic switches. The commands are thin wrappers over Docker that resolve app and workload names.
Experience
helios logs dragon-writer web -f instead of ssh, docker ps and copying ophelia-loom-production-production-c1afaf88aaf5-core-api-1. helios status shows apps, health, version, last deploy, certificate expiry and disk on one screen.
Why
These are the commands you run every day, and today they need Docker knowledge and long names.
Unlocks
Everything else feels smaller once this exists. Loom's log view (32) uses the same name resolution.
3

One line per step, a receipt per operation

SmallImpact: Medium
Summary
CLI output like loom core create: one line per step that updates in a terminal and prints in full in logs. Every operation writes a JSON receipt, and helios history lists them.
How it works
One renderer shared by all commands. Receipts record inputs, digests, timings, outcome and the exact changes, with secrets redacted, kept locally and synced to Loom.
Experience
A deploy reads as a short story, and any past deploy can be reopened.
Why
Ophelia's plans and receipts were its best idea, buried under verbose output. Keep the record, fix the reading.
Unlocks
Agent-safe operation (34) is built on receipts; the fleet view (32) shows them.
4

--plan on everything that changes something

SmallImpact: Medium
Summary
Any mutating command prints the exact changes and exits; --yes for scripts.
How it works
Every operation is built as a plan (containers, files, DNS records, secret names, cron entries) before it's applied. --plan stops after building it and shows a diff.
Experience
helios deploy begamin --plan shows the image, the routes, the DNS record it would create and the secrets it would inject, and changes nothing.
Why
Ophelia's dry run survives, without the confirmation-token ceremony around it.
Unlocks
Plan digests are what approvals (34) bind to.
5

Manifest schema for your editor, and helios check

SmallImpact: Medium
Summary
Publish the manifest's JSON Schema so editors autocomplete and flag mistakes as you type. helios check validates a repository before any push.
How it works
The schema is generated from the Go types. check validates the manifest, confirms the Dockerfile and health path exist, that declared secrets have names, and that ports and routes don't collide.
Experience
Red squiggles in the editor instead of a failed deploy ten minutes later.
Why
Catches most manifest mistakes before they reach a machine.
Unlocks
Templates (30) and the converter (22) produce schema-valid files.
6

Verification checks in the manifest

SmallImpact: Medium
Summary
Keep kylebegeman.com's verify list and extend it: a URL returns a status, contains text, a JSON path equals a value, or answers within a time limit.
How it works
Checks run after every deploy against the new revision before traffic switches, and again on a schedule as health.
Experience
A deploy that renders the wrong page never goes live. You see "career-data: ok, 84 ms".
Why
Only static v1 apps have this today, and it's the cheapest proof that a deploy did what it should.
Unlocks
Health and alerts (25) reuse the same checks.
7

Certificate readiness inside the deploy

SmallImpact: Medium
Summary
Before traffic switches to a new hostname, Helios waits until Caddy holds its certificate, with a clear status line.
How it works
Helios checks DNS first and then asks Caddy's admin API for the certificate state, so a wrong record reads "loom.begam.in points at 1.2.3.4; this machine is 5.6.7.8" instead of a five-minute timeout.
Experience
The first deploy of a new domain works the first time.
Why
Replaces Loom's certificate warm-up hack and the single-check race that caused rollbacks.
Unlocks
Previews (30) create hostnames constantly and need this to be boring.
8

Bounded logs, resource limits, low-priority builds

SmallImpact: Medium
Summary
Every container gets log rotation, a memory limit, CPU shares and a restart policy by default. Image builds run at low priority.
How it works
Defaults in Helios, overridable per workload. Builds get a CPU weight and I/O priority below live workloads.
Experience
A build doesn't stall Dragon Writer, and a chatty app can't fill the disk with logs.
Why
No Ophelia renderer sets log rotation, and Loom's builds share memory with your sites.
Unlocks
Capacity signals (19) mean something once limits exist.
9

Garbage collection that only touches what Helios owns

SmallImpact: Medium
Summary
helios gc removes retired revisions' images, volumes, networks and build cache by retention, and never runs a host-wide prune.
How it works
Everything Helios creates carries labels for app and revision. GC walks its own state, reports reclaimable space, and runs on a schedule or when disk crosses a threshold.
Experience
"Reclaimed 4.1 GB: 6 images and 12 volumes from revisions older than 14 days."
Why
145 orphaned volumes on the personal box, 30 GB of build cache elsewhere, and a prune --all in Loom's deploy that could delete other apps' images.
Unlocks
Safe multi-app hosts.
10

Scheduled jobs and one-off tasks as workloads

MediumImpact: High
Summary
kind: cron with a schedule, overlap policy, timeout, missed-run catch-up and failure alerts. helios run <app> -- <cmd> for migrations and admin commands.
How it works
Cron workloads are containers Helios starts on schedule with the app's image, env, secrets and network, journaled like deploys. run does the same once, streams output and records a receipt.
Experience
Dragon Writer's hourly backup becomes three lines of manifest. Loom's owner code is helios run loom-core -- deployment-bootstrap issue.
Why
Today those are a while true; sleep container and an improvised docker run on the data network.
Unlocks
Backups (24) and drills are cron workloads themselves.
11

Cloudflare DNS that follows the app

MediumImpact: High
Summary
Routes in the manifest create, verify and remove their DNS records. helios dns audit finds records that point nowhere.
How it works
A zone-scoped token in the secrets store. Each route declares proxied or DNS-only. The deploy refuses when a record disagrees with the machine, and retiring an app removes its records.
Experience
No more Cloudflare dashboard trips. begam.in answering 525 would have shown up as "record without a route".
Why
You said yes to this, and previews need to create hostnames on the fly.
Unlocks
Previews and launch (30), graduate (31).
12

Deploy from a backup

Small to MediumImpact: High
Summary
helios deploy dragon-writer --restore <archive> seeds the database and volumes before the first start.
How it works
The same restore path a drill uses, pointed at a local archive or a Backblaze snapshot, run before the app's first revision starts. The manifest's verify command confirms the data.
Experience
Dragon Writer's return to the final box is one command, and disaster recovery onto a fresh machine is the same command.
Why
This week's restore was psql by hand.
Unlocks
Depends on the backup format (24). Graduate (31) is this plus a cutover.
13

Bandwidth-aware backups and drills

SmallImpact: Medium
Summary
Backups upload only what changed, drills download only what they need, and Helios tracks the daily download budget and warns before a cap.
How it works
restic's deduplication keeps hourly backups small. Drills use the latest snapshot. A per-provider budget is tracked in the state store, with a monthly cost estimate per app.
Experience
A restore drill never uses up the day's download allowance the way today's mirror did.
Why
The Backblaze download cap stopped the mirror at 7.1 of 10 GB.
Unlocks
Restore drills (24) can run weekly without surprises.
14

App registry with purpose and provenance

SmallImpact: Medium
Summary
Every app records its repository, a one-line purpose, its owner (personal or BrainTreeLabs), domains, last deploy (commit, who, when), last backup and machine.
How it works
Fields in the manifest plus facts Helios records. helios ls shows them, and anything running that Helios doesn't own is listed as unmanaged.
Experience
One list answers "what runs where, and why", the question that took a day this week.
Why
A forgotten Spaceship server and five dead Vultr addresses in your SSH files.
Unlocks
The fleet view (32) is this list across machines.
15

Integration credentials in one place

SmallImpact: Medium
Summary
Cloudflare, Backblaze, GitHub deploy keys and registry credentials live in the secrets store, scoped to the apps that use them, with an audit of use and age.
How it works
bedrock integrations lists each credential, which apps use it, when it was last used and rotated. Rotation updates every use.
Experience
The VPS_HOST and VPS_SSH_KEY secrets in four repositories go away. One place to rotate a Cloudflare token.
Why
"Too many random pieces across accounts and logins."
Unlocks
Depends on the secrets store (26).
16

Maintenance windows

Small to MediumImpact: Medium
Summary
helios host maintain, on demand or scheduled: apply OS updates, reboot if required, bring apps back in order, run every verify check, report.
How it works
Drain new deploys, snapshot state, update, reboot, then start workloads in dependency order and run health and verify checks. Alert on anything that didn't come back.
Experience
Reboots stop being something you hope about.
Why
Both machines had a reboot pending.
Unlocks
Helios's own upgrade (18) uses the same window.
17

Environments and promotion

MediumImpact: Medium
Summary
An app can have staging and production, on the same or different machines. bedrock promote moves the exact image digest and shows the config diff.
How it works
Environments share one manifest with per-environment overrides. Promotion reuses the built image and runs the same verify checks.
Experience
Loom's staging-to-production flow without copying manifests. Dragon Writer's staging file becomes an override block.
Why
Today's staging is a second copy of everything.
Unlocks
Previews (30) are environments that appear and disappear.
18

One-line install, self-upgrade with rings

SmallImpact: Medium
Summary
One static binary. helios upgrade stages the new version, restarts, and rolls back if the new daemon fails to start. The business machine upgrades a day before the personal one unless you say otherwise.
How it works
Two binaries on disk, an atomic symlink switch, a health check inside the systemd start timeout, rollback on failure. Loom shows the version per machine.
Experience
An upgrade is a line in the changelog, not a per-release Python environment.
Why
Ophelia's install grew a launcher chain that broke the watchdog.
Unlocks
The test lane (36) exercises upgrade and rollback on every release.
19

Traffic and resource signals per app

MediumImpact: Medium
Summary
Requests per day, approximate visitors, p95 latency, CPU, memory and disk per app, kept as 90-day rollups.
How it works
Parsed from Caddy's access logs and container stats by the daemon, stored locally, shown in helios status and Loom.
Experience
"begam.in: 1,200 requests a day, 40 MB, 2% CPU" beside every app.
Why
Capacity warnings, and the evidence for graduating a product.
Unlocks
Graduate (31) decisions and capacity alerts (25).
Items 20 to 37

Major features, systems and refactors

The systems that make Helios a platform rather than a deploy script: the kernel, the contracts, and the four capabilities Ophelia specified but never built.

20

One binary, one kernel

MassiveImpact: Transformational
Summary
bedrock is one static Go program: the CLI, the host daemon and the same code on your Mac. One state store, one layout on disk, one authenticated API.
How it works
SQLite journals every operation as plan, steps and receipt, with leases so a crash resumes or compensates. /var/lib/bedrock and /etc/bedrock are the only paths. The daemon owns Docker and Caddy and pings systemd's watchdog itself. A Unix socket locally, mutual TLS outbound to Loom, nothing unauthenticated.
Experience
Copy one file, run helios host setup, deploy. Upgrading is replacing the file.
Why
Removes per-release Python environments, three state roots, two edges on the same ports, two APIs and the launcher chain behind the 0.6.18 watchdog bug.
Unlocks
Everything below.
21

Host setup and reconcile

LargeImpact: High
Summary
helios host setup turns a fresh Ubuntu or Debian box into a Helios host in minutes. helios host reconcile detects drift and repairs it.
How it works
Docker CE, the Caddy edge, UFW, swap, NTP, unattended security updates, key-only SSH, fail2ban, the local image registry, journald limits and the hostname, from a stored profile. Safe to rerun. host inventory reports what's there.
Experience
OS reinstall to first deploy in under ten minutes, on either machine, as many times as you like.
Why
Ophelia listed this as deferred, so Loom's installer had to write its own.
Unlocks
The test lane (36), launch (30), graduate (31).
22

One app manifest, with a converter

LargeImpact: High
Summary
A single manifest format covering what v1 and v2 each had half of: workloads, data, routes, secrets, checks, backups, resources, environments and the registry fields.
How it works
Strict validation with helpful errors and a published schema. bedrock manifest convert reads an Ophelia v1 or v2 file and writes the new one with a diff that explains each change.
Experience
One file per app that reads top to bottom: what it runs, where it lives, what it needs, how it's checked, how it's backed up.
Why
v1 had backups, packs and add-ons. v2 had the kernel semantics. Nothing had both.
Unlocks
Every feature reads this one contract.
23

Deploy pipeline with real rollback

LargeImpact: High
Summary
Build from git on the host (or pull an image), start the new revision beside the old, gate on health, verify checks and certificate readiness, switch traffic atomically, record a receipt. helios rollback in seconds.
How it works
Images build into the local registry and are pinned by digest. A revision bundles image, config and secrets version. Rollback re-points to the previous revision, including its secrets. N revisions are retained. Migrations are a gated step with a backup taken first.
Experience
Push, watch one line per step, done. If it's wrong: helios rollback begamin.
Why
Replaces the 3,441-line deploy script and the 2,034-line rollback script that imports Ophelia's internals, and takes GitHub Actions out of the path.
Unlocks
Previews (30), promotion (17), the Core lifecycle (33).
24

Backups that run, drills that prove them

LargeImpact: Transformational
Summary
Every app with data gets scheduled backups to its own Backblaze bucket, freshness monitoring, and a scheduled restore drill that restores into a throwaway container and verifies the data.
How it works
Postgres dumps and volume snapshots go into a restic repository (encrypted, deduplicated, with a retention policy). The drill restores the latest snapshot, starts the app in isolation, runs its verify command (row counts, file counts, a URL) and reports recovery point and recovery time. A failed drill alerts. helios restore for the real thing.
Experience
A weekly line in Loom: "Dragon Writer: backup 42 minutes ago, drill passed Sunday, 5,446 words in 24 chapters."
Why
Ophelia validated backup settings and never ran them. begam.in has none. Olive's work survived because the app wrote its own script.
Unlocks
Deploy from backup (12), graduate (31).
25

Health, observation and alerts, Loom first

LargeImpact: Transformational
Summary
Continuous checks of every app and host, with alerts that reach you the same day.
How it works
Workload health, verify URLs, certificate expiry, disk, memory and CPU, backup freshness, drill results, reboot-required and Helios version, each with hysteresis so nothing flaps. Routing to Loom push first, email as fallback, with dedupe, escalation and acknowledgment. Each machine also checks the other's public URLs from outside, through Cloudflare when proxied, so a dead host can't hide.
Experience
One notification: "dragonwriter.begam.in has returned 404 for 10 minutes." Then nothing until it changes.
Why
75 days.
Unlocks
The fleet view (32) is the same data at rest.
26

Encrypted secrets store

Medium to LargeImpact: High
Summary
Secrets are sealed on the host, scoped per app, set from stdin, a prompt or Loom, injected at start, versioned with revisions, and never in arguments, logs or backups.
How it works
A store keyed by the host identity with a recovery key printed once, for 1Password. Values are injected into containers through tmpfs env files. Reads are audited. Rollback restores the matching secrets version.
Experience
helios secret set begamin B2_KEY prompts, nothing echoes, the next deploy has it.
Why
Loom's bootstrap writes env files by hand today, and secrets end up inside backups.
Unlocks
Integrations (15), managed data services (27).
27

Managed data services per app

LargeImpact: High
Summary
data.postgres: true gives an app its own Postgres with a database, role and password in the secrets store, the URL injected, backups included and a major-version upgrade command. The same for Redis and an S3-compatible object store.
How it works
One container per app per service, pinned major version, resource limits, on the app's data network only. Credentials are generated and rotated by Helios. Backups (24) know how to dump and restore each.
Experience
Three lines of manifest replace a hand-run Postgres and a shared password.
Why
Dragon Writer needs Postgres 16, Ophelia v1 shared one password across apps, and Loom has object storage.
Unlocks
Launch (30) needs this to be one step.
28

Per-app isolation

LargeImpact: High
Summary
Each app runs as if alone: its own networks, no shared credentials, non-root, read-only root filesystem and no-new-privileges by default, resource limits, and privileged workloads declared explicitly.
How it works
Edge and data networks are joined only where the manifest says. Loom's Runner is a declared privileged workload kept on its own network. helios exposure reports each app's privileges, ports and mounts.
Experience
A bug in a launchpad product can't reach Loom's database.
Why
Ophelia's own docs warn against running sensitive workloads beside the Runner, and never built the isolation.
Unlocks
Safe co-hosting on both machines; previews from untrusted branches.
29

Git-native deploys

Medium to LargeImpact: High
Summary
git push bedrock main deploys. Or a GitHub webhook does. Or helios deploy from the Mac over one SSH session. Actions become optional.
How it works
A per-app deploy remote on the host with an app-scoped key. The receive hook builds and deploys and streams the step lines back to the terminal. Webhook mode receives pushes for a branch.
Experience
The way Heroku felt, on your own machine, with your own logs.
Why
Four repositories each carry VPS_HOST and VPS_SSH_KEY secrets and a workflow, and an Actions budget blocked a release.
Unlocks
Previews and launch (30).
30

Launchpad: bedrock launch and previews

ShippedLargeImpact: Transformational
Summary
bedrock launch <repo> takes a product from repository to live: template detection, manifest, domain, DNS, certificate, database, backups, checks, first deploy. Every pushed branch gets a preview at <branch>.<app>.preview.<domain> with its own database copy, removed on merge or inactivity.
How it works
Templates for Next.js, static, Go and Node services. Previews are ephemeral environments (17) seeded from the latest backup (24), with DNS (11) and certificates (7) handled. A size cap and an idle timeout keep them cheap.
Experience
An idea on Monday is a URL on Monday. The business machine's whole purpose in two commands.
Why
The launchpad is why the OVH box exists.
Unlocks
Traffic signals (19) and graduate (31) complete the lifecycle.
Shipped
Partly, in 0.7.6. bedrock launch <repo> takes a repository from nothing to running: fetch it, work out what it is, write the manifest it is missing, deploy it. What it will infer is deliberately narrow, because a wrong guess becomes a manifest somebody has to debug. Previews arrived in 0.7.7: helios preview up deploys a branch as an app beside the one it is a branch of, with its own empty database and every route behind a sign-in. They did not need ephemeral environments (17) after all; an app was already the right unit.
31

bedrock graduate: move an app to its own machine

ShippedMassiveImpact: High
Summary
Move an app and its data to another machine with a rehearsal, a short write freeze, a DNS cutover and a rollback window. helios move does the same between your two boxes.
How it works
Provision the target (21), restore the latest backup there (12), rehearse verification, freeze writes, sync the delta, start, verify, switch DNS (11), keep the source for a window, then retire it.
Experience
A product with traction leaves the launchpad in an afternoon, and the record shows every step.
Why
Ophelia specified this as major features 1 to 4 and never built any of it.
Unlocks
The model you described: launch, prove, graduate.
Shipped
Partly, in 0.7.6, as helios move. Two commands, one per machine, with the backup bucket as the channel and a handoff that carries no secrets. helios move secrets seals the app's secrets to the target's key so its restored database opens there. Both machines must read the same bucket under the same password; a target that cannot is refused rather than silently finding nothing. One command driving both machines needs a channel between them, which is the enrollment link tabled with 32.
32

Helios and Loom: enrollment and the fleet view

TabledMassiveImpact: Transformational
Summary
Each machine enrolls with Loom and keeps an outbound, mutually authenticated link. Loom shows every machine, app, deploy, backup, drill, alert and log, and is where approvals happen.
How it works
Enrollment bound to a confirmation you see in Loom; signed, scoped commands with replay protection; an event stream with cursors; a Fleet mode in Loom built on the registry (14), the signals (19) and the receipts (3).
Experience
Open Loom, see both machines and every app, approve a production deploy from your phone.
Why
Loom is the UI. Ophelia's fleet control was turned off for new Cores, but its protocol design was sound and carries over.
Unlocks
Agent operation (34), Loom sign-in (35), the Core lifecycle in the app (33).
Tabled
Tabled on September 21, 2026, for as long as the estate is two machines. A fleet view is a way to see more machines than you can hold in your head, and two is not that number: helios status over SSH already answers every question this would answer, on both machines, in about as long as it takes to open an app. The cost on the other side is an enrollment protocol, signed and scoped commands, replay protection, a cursored event stream and a whole new mode in Loom, all of which have to keep working forever. Revisit when there are enough machines that a missed one is plausible, or when someone other than Kyle needs to see the estate without an SSH key. Nothing here is wrong and nothing is being deleted; it is waiting for a reason. See the direction.
33

Loom Core's own lifecycle on Helios

LargeImpact: High
Summary
The Core, processor, Runner and data services become Helios apps. loom core create becomes host setup plus a deploy. Upgrade, rollback, backup and restore of the Core run through Helios, from the app, with no Actions.
How it works
One Loom manifest replaces the four Ophelia manifests and the data-authority scripts. The Runner is a declared privileged workload (28). CORE-03 and CORE-04 build on Helios's API instead of shell scripts. deploy/ophelia/ is deleted.
Experience
"Update Core" in the app does what a release does today.
Why
12,000 lines of glue, and CORE-02 to CORE-05 finish faster on one coherent base.
Unlocks
CORE-05, your fresh start.
34

Agent-safe operation

MediumImpact: High
Summary
Every command has --json and --plan. A plan has a digest. Applying requires that digest and, for production, an approval recorded in Loom. API tokens are scoped read-only, per app or per host.
How it works
Plans and receipts are signed. An agent can inspect, propose and rehearse, and can apply only what a person approved.
Experience
A Loom agent says "I'd like to deploy begamin, here's the plan", you tap approve, it runs, and the receipt names both of you.
Why
Ophelia's strategy called this "delegate to agents". It's Loom's whole premise.
Unlocks
Autonomous maintenance, and previews opened by agents.
35

Loom sign-in for any route

ShippedMediumImpact: High
Summary
auth: loom on a route means only signed-in Loom identities reach it, with no per-app auth code.
How it works
Caddy forward-auth to the Core's session endpoint, allowing the owner or a named group. Works for admin pages, previews, personal tools and demos.
Experience
A weekend project gets a login by adding one line.
Why
Cloudflare Access goes away with direct TLS, and previews need protecting.
Unlocks
Personal projects on the personal box are safe by default.
Shipped
In 0.7.6. A route marked auth: loom is put behind the Core's sign-in by the edge, through Caddy forward auth against a new GET /api/cloud/auth/verify in the Core. A route that asks for a sign-in and cannot get one is refused while planning, and is never served open.
36

Real-host test lane

MediumImpact: High
Summary
Every release proves itself on a machine that's wiped and rebuilt: host setup, fixture apps, backup, drill, rollback, retire, self-upgrade, reboot.
How it works
A workflow rents an hourly VM (or resets the Hostinger box while it's the test bed) and runs the whole lifecycle with static, web-plus-Postgres and cron fixtures. A Docker lane in CI covers the rest.
Experience
A green check that means "this works on a real server", not "the unit tests pass".
Why
Ophelia had no Docker or VPS lane, and the watchdog bug surfaced in production.
Unlocks
Confidence to change anything.
37

Ophelia to Helios migration

MediumImpact: High, short term
Summary
bedrock migrate reads an Ophelia host, converts manifests, exports data and secret names, and produces an import plan for the new machine.
How it works
Reads both the v1 runtime and the v2 root, applies the converter (22), packages data through the backup format (24), and writes a checklist with verify steps for moving day.
Experience
Moving day is a plan you read, then run, then check.
Why
Four apps and Loom have to move once, and it should be the last time the old layout matters.
Unlocks
Decommissioning Ophelia.
Where to start

Three shortlists

Highest return

  1. Backups that run, drills that prove them
  2. Health and alerts, Loom first
  3. Deploy pipeline with real rollback
  4. Host setup and reconcile
  5. Cloudflare DNS that follows the app
  6. Everyday commands
